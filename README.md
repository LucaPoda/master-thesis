# Semantic Scene Graph - Simulator & Visualizer

This project is a simulated system capable of converting an agent's dynamic visual perception into a **Semantic Spatial Graph (Semantic Scene Graph)**. It serves as a study in translating pure geometric 3D vision into topological and relational semantic data.

## 🛠️ Component-Based Architecture

The system is decoupled using the **Single Responsibility Principle (SRP)** and **Dependency Inversion**. Components communicate via an untyped generic data buffer, mimicking ROS publisher/subscriber mechanics.

### `PerceptionInput` (Topic Buffer)

Acts as a generic subscriber payload. Concrete perception or reasoning components dynamically pull "topics" (e.g., `agent_state`, `world_objects`) from this buffer. If an expected data field is missing, components fail gracefully with a `ValueError`, simulating an unpopulated topic.

### Core Pipelines

1. **`WorldState`**: Ground-truth definition of the 3D map environment (coordinates, objects, and AABBs).
2. **`GraphicEngine`**: Panda3D visualizer and physical engine running broad-phase collision detection and 3D rendering.
3. **`PerceptionSystem`**: Simulates optical camera vision using 6-plane Frustum Culling algorithms mathematically driven by the agent's Yaw and Pitch.

## 🧠 Ego-Centric Spatial Reasoning (`spatial_reasoner.py`)

Nodes in the Semantic Graph are generated by evaluating the agent's perspective, mapping objects and their spatial relations.

The `GroundTruthSpatialReasoner` performs relational inference in the **Agent's Camera Frame**.
Instead of using fixed World Coordinates (Allocentric), objects are mathematically projected into relative coordinates based on the agent's Yaw (orientation).
Looking at the same two objects from opposite angles fundamentally changes their relative positions (e.g., what was left becomes right), correctly diverging the graph into distinct state nodes.

**Supported Pairwise Relations:**

- **`near`**: Evaluated if absolute 3D Euclidean distance is `< 8.0`. All directional relations depend on proximity.
- **Vertical (World-Z, requires horizontal XY overlap):** `on-top` (touching), `on-bottom`, `over` (floating above), `under`.
- **Directional (Ego-Centric Frame, transformed by Agent Yaw):** `left`, `right`, `front`, `back`.

## 🔗 Semantic Graph Tracker (`agent_state.py`)

The graph logic handles topological state transitions entirely independent of rendering.

- **`SemanticState`:** A combination of a `Set` of visible object IDs and a `Set` of immutable `SpatialRelation` dataclasses.
- **Identity Hashing:** State uniqueness is dictated by `SemanticState.to_frozen_key()`. Two states with the *exact same objects* but *different ego-centric relations* (e.g., turning around) will hash to completely different keys, spawning new topology nodes.
- **Undirected Edges:** Graph edges represent contiguous physical exploration. Moving back and forth between two known states reuses the same undirected transition edge.

## 🌐 Interactive Web UI (`index.html`)

A FastAPI/WebSockets daemon runs entirely in the background, streaming graph serialization to the browser without interrupting the 60 FPS Panda3D execution.

- **Pin / Lock Details:** Click on any node in the Vis.js canvas to "Pin" it to the sidebar (indicated by a red border). This allows users to lock the UI and freely scroll through dense lists of active spatial relations. Clicking empty space unpins it.
- **Edge Inspection (Deltas):** Clicking on an edge connecting two states reveals a bidirectional mathematical difference panel. It highlights **Added/Removed Objects** and **Added/Removed Spatial Relations** (styled with colored badges) to perfectly explain *why* the state transitioned.

## 🧪 Local Unit & Integration Test Suite

The project includes an exhaustive, fast, and 100% headless test suite executing via `pytest` without invoking any 3D graphics or Web Servers.

**Test Coverage Areas:**

1. **Core Data Structures:** Hashability, Immutability, `SemanticState` frozen keys.
2. **Graph Topology:** Node creation, idempotency (no duplicate states), cyclic traversal (reusing undirected edges).
3. **Ego-Centric Reasoning:** Negative coordinate boundaries, intersection limits, and perspective shifts (verifying that 180-degree Yaw inversions successfully alter horizontal relations).
4. **Edge Cases:** Headless pipeline integration, falsy inputs, empty map arrays, missing topics.

To execute tests instantly:

Bash

```
pytest tests/ -v
```

## 🔮 Future Developments & Architectural Reflections

Now that the foundation of the Semantic Scene Graph is established and thoroughly tested, the architecture is ready to transition from a passive representational mapping system into an environment for autonomous reasoning and decision-making. The following reflections map out the immediate next steps to tackle the challenges of autonomous exploration and robotics.

### 1. Semantic Inference and Querying

By treating the graph as a dynamic Knowledge Base, we can shift away from metric coordinate checking to high-level logical querying:

- **Declarative Queries:** Utilizing the topological structure to find configurations, such as the shortest path to a semantic state where "object A is left of object B."
- **First-Order Logic (FOL) Integration:** Wrapping the `SemanticState` with a rule engine (e.g., Prolog, PyDatalog, or Answer Set Programming) to deduce implicit relations that are not geometrically calculated (e.g., transitivity rules).
- **Constraint Satisfaction (SAT/CSP):** Implementing local search algorithms like Walk-SAT over the semantic state space to locate candidate nodes that satisfy complex, multi-clause logical goals.

### 2. Active Perception & Autonomous Exploration (Active SLAM)

Unlike classic metric SLAM, which simply aims to cover unknown coordinate grid cells, exploring a conceptual graph requires active observation:

- **Reactive Bootstrapping (Cold Mapping):** When starting with an empty graph, the agent must rely on local visual heuristics rather than a map. "Behavior-based exploration" techniques (like 360-degree panning or approaching distant clusters) will be used to generate the initial nodes.
- **Semantic Frontiers & Information Gain:** Identifying nodes that are topologically under-explored (e.g., objects viewed from only a single perspective, or states with high entropy and low connectivity).
- **Active Planning:** Once the graph reaches sufficient density, the system will pivot from reactive movement to deliberative planning, routing the agent toward known semantic frontiers before triggering further local exploration.

### 3. The Symbol Grounding Problem & Geometric Execution

To bridge the gap between high-level symbolic goals and the continuous physics of robot movement, we must connect abstract state transitions to continuous local control:

- **Ego-Centric Action Primitives:** Graph edges will not map to global metric trajectories. Instead, they will act as triggers for local control policies (e.g., `Orbit_Target(A, B, CW)` or `Approach_Object(A)`), guiding the robot's hardware using real-time visual servoing until the target semantic relation becomes true.
- **State Stability & Hysteresis:** Micro-movements or camera noise can easily oscillate the viewing angle, causing an explosion of redundant states (chattering). Future implementations will require relational hysteresis (e.g., applying angular tolerances before flipping a `left`/`right` state) and multi-frame stability filters to solidify nodes.

### 4. Moving Towards Real-World Computer Vision

While the current framework operates on a solid 3D ground truth, the eventual integration with real-world perception models (like VLMs or YOLO3D) will introduce the final layers of complexity:

- **Probabilistic Graphs:** Absolute certainty will be replaced by factor graphs to manage perceptual uncertainty, tracking confidence values for observed relations (e.g., $P(\text{Left}(A, B)) = 0.85$).
- **Semantic Perceptual Aliasing:** Implementing Semantic Loop Closure strategies to distinguish between two physically different but visually identical areas (e.g., identical office desks in different rooms) that generate the same `SemanticState`.
